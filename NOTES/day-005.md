# 🧠 What I Learned

## Deployment and nonce
- Two different addresses: the **manager** (= `msg.sender` in the constructor, the deployer) and the **contract address** (derived from deployer address + nonce).
- The nonce increases after every transaction an account sends, even a plain ETH transfer. Deploying twice from the same account gives two different contract addresses.

## Randomness
- Every validator must reach the same result, so true randomness is impossible inside a contract.
- Anything readable on-chain is predictable. Manager, players and validators can all exploit a pseudo-random winner. Production protocols use an oracle such as Chainlink VRF.

## `private` is not secret
- `private` only restricts who can *call* a function (the contract itself). All data on-chain is public.

## Reverted call in Remix
- Calling `pickWinner()` with Value = 0.25 ETH reverted because `pickWinner()` is not `payable`. Remix keeps the Value field between calls.

# 🔍 Audit Finding (found by me)

`resetPlayers()` was `public restricted`. A dishonest manager could: reset players, enter alone with 0.1 ETH, call `pickWinner()` and take the whole pot. Fixed by making it `private`.

Other notes from review:
- `players.length == 0` → modulo by zero; add a `require`.
- `transfer` forwards only 2300 gas; a contract winner without a receive function would block the lottery.
- Update state before sending ETH (checks-effects-interactions).
- Remix flags `pickWinner()` as "infinite gas": `abi.encodePacked(players)` encodes an unbounded array.
