# 🧠 What I Learned

## Deployment is a transaction too

Calling a function on an already-deployed contract and *deploying* a contract are different things. Deployment is itself a special transaction: `to` is empty, `data` is the contract's creation bytecode, and the constructor runs exactly once as part of that transaction. This is still the weakest point from today — worth a dedicated session.

## Execution order

A validator building a block executes transactions via the EVM *while* building the block (to know the resulting state) — not after the block is already validated by everyone else. Other validators then re-execute/verify and attest. Execution happens first, consensus confirms it.

## call() vs send(), the real reason

`call()` runs locally, on a single node, with no network broadcast and no state change — so no consensus is needed, hence free. `send()` must be executed and agreed upon by every validator to update the shared state, which is the actual cost gas is paying for (not just "because it writes").

## Function selectors

- `keccak256("functionName(type1,type2,...)")` produces a hash; the **first 4 bytes** of that output are the function selector.
- The deployed bytecode has a dispatcher, fixed at compile time, that only matches its own real selectors.
- The frontend computes a selector from the ABI and sends it in `data`.
- Stale ABI → wrong selector → no match in the dispatcher → revert at execution time (or a fallback function runs, if one exists). Not a compile-time error on either side.
