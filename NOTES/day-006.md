# 🧠 What I Learned

## Project setup
- `package.json` is generated by npm (`npm init -y`, then `npm install --save-dev ...`), never written by hand.
- Anything the code `require`s must be installed: Hardhat config needed `dotenv`, not yet installed in `lottery` (error: `Cannot find module 'dotenv'`).
- `.gitignore` must exist before the first `git add` because `.env` holds secrets (`PRIVATE_KEY`, `INFURA_URL`). `.env` is ignored and was never committed.
- Hardhat 2 warns on Node 23 (non-LTS); it works for now, Node 22 LTS is the fallback.

## ethers v5 → v6
- `lottery.deployed()` → `await lottery.waitForDeployment()`.
- Numbers are `BigInt` in v6.

## How to write a test
- Prepare → act → assert (`expect`).
- `beforeEach` redeploys a fresh contract so tests do not share state.
- `lottery.connect(player1)` calls as another account; `{ value: ethers.parseEther("0.1") }` sends ETH (needs `payable`).
- Revert test pattern: `await expect(call_without_await).to.be.revertedWith("exact message")`.

## A green test proves nothing by itself
- An empty test passes. A call without `await` or without `expect` passes. A test that checks something already true passes.
- Sabotage check: remove `restricted` from `pickWinner()`; the access-control test must turn red. It did (reverted with panic 0x12, division by zero, because no player had entered — the test went red for a side reason; entering a player first would make it fail for the right one).

# ⚠️ Mistakes To Remember

- Put `await` inside `expect(...)` instead of in front of it, so the revert escaped before `expect` could check it.
- Revert message in the test did not match the contract's message.
- Left tests with no `expect` / no `await`, giving false greens.
- Compared balances with `greaterThan` instead of the exact amount.
- Did not install `dotenv` after copying the Inbox config.
- Explained `beforeEach` as "can't test other functions after one deploy"; the real reason is shared state between tests.
